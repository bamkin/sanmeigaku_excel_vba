# 受付 実装メモ（開発順序4）

申込 → 決済 → 生成 → 承認 → 送付。`uketsuke/` に実装。周辺サービスはアダプタ越しで、鍵が無ければダミーで全導線が通る。

## 構成

| ファイル | 内容 |
|---|---|
| uketsuke/db.py | SQLite（単一ファイル、`ROKUJU_DB`、既定 `rokuju.sqlite3`）。orders（申込・宿命表JSON・状態）、generations（生成結果・禁則チェック・usage・エラー）、approvals（承認・再生成・送付の履歴。承認時の本文も保存）、deliveries（送付記録） |
| uketsuke/adapters.py | 決済（Stripe Checkout／ダミー）、メール（Resend／ダミー）、生成（Claude API／ダミー）。`adapters_from_env()` で環境変数から選ぶ |
| uketsuke/flow.py | 導線の本体。`create_order` → `mark_paid` → `run_generation` → `approve` → `send`。`regenerate` は履歴を残して生成し直す |
| uketsuke/routes.py, templates/ | FastAPI ルーター。shindan.app に組み込む（無料診断と同じプロセス・同じ見た目） |
| tests/test_uketsuke.py | ダミーアダプタで申込から送付まで通す。認証、入力検証、生成失敗の記録、webhook |

```
uvicorn shindan.app:app --reload
ROKUJU_GENERATOR=dummy uvicorn shindan.app:app --reload      # API を呼ばずに導線を通す（samples の実機2 を返す）
```

## 経路

| 経路 | 誰が | 何をする |
|---|---|---|
| GET /apply?birth= | 申込者 | 申込フォーム（docs/20 の5問＋任意1問、基本情報、プラン）。無料診断の結果画面から生年月日を引き継ぐ |
| POST /apply | 申込者 | 検証して保存（状態 決済待ち）、宿命表をこの時点で算出して保存。決済ページへ 303 |
| GET/POST /pay/dummy/{id} | 申込者 | Stripe の鍵が無いときだけ。「支払う（ダミー）」で入金済みにして生成を始める |
| POST /webhook/stripe | Stripe | `checkout.session.completed` で入金済みにして生成を始める。署名は `STRIPE_WEBHOOK_SECRET` があれば検証 |
| GET /order/{id} | 申込者 | 受付番号と状態。送付済みなら送り先を表示 |
| GET /admin | 逆井 | 申込一覧（状態・生年月日・宛名・プラン） |
| GET /admin/order/{id} | 逆井 | 申込回答、生成の結果（note・禁則チェック・字数・エラー）、本文のプレビュー、Markdown のまま加筆して承認、再生成、PDF の試し刷り、送付、履歴 |
| POST /admin/order/{id}/generate, regenerate, approve, send | 逆井 | それぞれの操作。送付は承認済みのときだけ（409） |
| GET /admin/order/{id}/pdf | 逆井 | 承認済み本文（無ければ最新の生成）を PDF にして表示 |

## 状態

決済待ち → 入金済み → 生成中 → 承認待ち（または 生成失敗） → 承認済み → 送付済み。
承認画面のボタンは状態に応じて出る（入金済み・失敗なら「生成する」、承認待ち・承認済み・失敗なら「再生成」、承認済みなら「送付」）。承認済みでも加筆して承認し直せる。送付は承認時点の本文（approvals の最新 approve）を使う。

## 環境変数

| 変数 | 意味 | 無いとき |
|---|---|---|
| ROKUJU_DB | SQLite のパス | `rokuju.sqlite3` |
| ROKUJU_ADMIN_PASSWORD | 承認画面の Basic 認証（ユーザー名は任意） | 認証なし。画面に注意書きが出る |
| ROKUJU_BASE_URL | 決済の戻り先に使う外向き URL | リクエストの Host から組む |
| STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET | Stripe Checkout（`pip install stripe` が要る） | ダミー決済ページ |
| RESEND_API_KEY, ROKUJU_MAIL_FROM | Resend でメール送付（PDF 添付） | コンソールに出して `outbox/`（`ROKUJU_OUTBOX`）に PDF を保存 |
| ROKUJU_GENERATOR=dummy | API を呼ばず samples/1973-11-23_実機2.raw.md を本人の宿命表で後処理して返す | Claude API（seisei。`ANTHROPIC_API_KEY` か `ROKUJU_ANTHROPIC_API_KEY`） |
| ROKUJU_LINE_URL | 送付メールに載せる LINE 公式のリンク | 載せない |
| SEISEI_MODEL, SEISEI_EFFORT, SEISEI_FALLBACK | 生成層と同じ | |

## 決めたこと

- **生成は決済後にバックグラウンドで一回**（FastAPI の BackgroundTasks。単一プロセスの中で走る）。4〜5分かかるので、承認画面は「生成中」を表示して読み込み直してもらう。失敗は例外を外に出さず generations.error に残し、状態を「生成失敗」にして承認画面から再生成できる
- **宿命表は申込時に算出して保存**。再生成はこの JSON から何度でもできる
- **完全版も承認後に送付**（docs/00 §1）。無人化するときは `run_generation` の後に `approve`＋`send` を続けるだけ
- **申込者に見せるのは受付番号と状態だけ**。本文は PDF で送る
- **Stripe の金額は db.PLANS（完全版 3,980／監修版 9,800）**。通貨 JPY は小数なし
- 承認画面の本文編集は Markdown のまま。プレビューは `markdown` ライブラリで描画（PDF と同じ変換）

## 確認待ち

1. 申込フォームの文言（docs/20 のまま）とプランの説明文。LP が決まったら差し替える
2. 送付メールの文面（`flow.mail_body`）。件名「六十の風景 — 鑑定書をお届けします」
3. 承認画面の認証は Basic 認証一段。公開前に `ROKUJU_ADMIN_PASSWORD` を必ず設定する
4. 監修版の「逆井が一読・加筆」と完全版の「承認」は、いまは同じ画面・同じ操作。区別するなら一覧の表示だけで足りる
5. 決済前に離脱した申込（決済待ちのまま）の掃除は未実装。一覧に残る
